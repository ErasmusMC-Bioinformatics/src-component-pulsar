Snellius Connection

This Pulsar server does not execute jobs itself: every job is submitted to Snellius over its SLURM REST API and runs — and is accounted — under the Snellius account of {{ slurm_user | default('NOT CONFIGURED', true) }}. The credentials were provided as workspace parameters when this machine was created.

Renewing your Snellius token

SLURM tokens (JWT) expire. When jobs stop submitting with authentication errors:

1. On a Snellius login node, generate a fresh token (valid 24 hours):

scontrol token lifespan=86400

2. On this machine, replace the SLURM_JWT=... line in /etc/pulsar/slurm_proxy.env, then restart Pulsar:

sudo nano /etc/pulsar/slurm_proxy.env
sudo systemctl restart pulsar

Testing the Snellius connection

sudo -u pulsar bash -c 'set -a; . /etc/pulsar/slurm_proxy.env; set +a; squeue'

A job listing (even an empty one) means endpoint, token and username all work. An authentication error usually means the token expired — renew it as above.

Important Notes:
  • Job files must be accessible on Snellius; the default working directory is /home/{{ slurm_user | default('<user>', true) }}/.
  • All jobs from this Pulsar count against that account's budget on Snellius.

Connect to New Galaxy Workspace

When creating a new Galaxy workspace on SURF Research Cloud, copy and paste these values into the workspace parameters:

Pulsar Configurations

Copy this entire line (including the brackets):

[{url: https://{{ workspace_fqdn | default('localhost', true) }}, private_token: {{ pulsar_token | default('unknown', true) }}, docker_enabled: true}]

Paste this into the "Connect existing Pulsar" parameter field.

Tool Mappings

Example: send BWA and Bowtie2 tools to this Pulsar server:

[{tool_id: bwa, environment: remote_{{ workspace_fqdn | default('localhost', true) | replace('.', '-') | replace('_', '-') }}_basic}, {tool_id: bowtie2, environment: remote_{{ workspace_fqdn | default('localhost', true) | replace('.', '-') | replace('_', '-') }}_basic}]

Paste this into the "Send tools to Pulsar" parameter field.

Galaxy generates two environments for this Pulsar: remote_{{ workspace_fqdn | default('localhost', true) | replace('.', '-') | replace('_', '-') }}_basic for regular tools and remote_{{ workspace_fqdn | default('localhost', true) | replace('.', '-') | replace('_', '-') }} for Docker/interactive tools — the environment name must match exactly, or Galaxy jobs fail with KeyError before submission.

Important Notes:
  • Copy the entire line including all brackets [ ].
  • Do NOT add extra quotes — ResearchCloud will handle this automatically.
  • Replace bwa and bowtie2 with your actual tool IDs.

Manual Pulsar configuration

If you have an existing Galaxy instance you want to keep, you can connect it to Pulsar by editing Galaxy’s job configuration.

YAML

Your job configuration is probably at /srv/galaxy/config/job_conf.yml.

runners:
  local:
    load: galaxy.jobs.runners.local:LocalJobRunner
    workers: 4
  pulsar:
    load: galaxy.jobs.runners.pulsar:PulsarRESTJobRunner

execution:
  default: docker_dispatch
  environments:
    local:
      runner: local

    ...
    remote_{{ ansible_hostname }}:
       runner: pulsar
       url: https://{{ workspace_fqdn | default('localhost', true)  }}
       private_token: {{ pulsar_token | default('unknown', true) }}
       dependency_resolution: remote
       manager: _default_
       # Uncomment the following to enable interactive tools:
       # docker_enabled: true
       # docker_set_user: null
       # docker_memory: "8G"
       # singularity_enabled: false
       # tmp_dir: true
       # outputs_to_working_directory: false
       # container_resolvers:
       # - type: explicit
       # require_container: True
       # container_monitor_command: /mnt/pulsar/venv/bin/galaxy-container-monitor
       # container_monitor_result: callback
       # container_monitor_get_ip_method: command:echo {{ workspace_fqdn | default('localhost', true) }}
